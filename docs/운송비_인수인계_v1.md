## 0. 이음비 안의 위치
- 이음비 서비스 묶음: 공간비, 절곡비, 노무비, (aiauction) + **운송비(신규)**
- 노무비와 같은 방식: **독립 앱**으로 시작, 이음비 공통 계정 체계에 포함
- 디자인: 노무비 시제품(`노무비/노무비_v2.html`)의 틀(이음비 배지 + 앱 이름, 역할 전환, 카드형 화면)을 따르고, 색상·글꼴은 이음비 홈페이지와 공간비 디자인에 맞춤
- **운송비 색상 확정 (2026-11-13)**: 대표색 `#4a8a8a`(teal), 잉크 `#2d5f6f`, 소프트 `#e6f2f0`, 단추 `#3a7575`, CSS 접두사 `us`(`.wm.us`). 이음비 tokens.css에 `--us-*` 변수 추가 필요(이음비 세션)
- 프로젝트 문서 폴더: `운송비/`

## 1. 무엇을 만드는가
생산자 → 화물기사 → 현장으로 이어지는 자재 운송을 연결하고, 관계자 모두가 실시간 운반 상황을 확인하게 한다.

| 역할 | 하는 일 |
|---|---|
| 발주자 | 발주 등록, 운송 요청, 진행 상황 확인, 운임 결제 |
| 생산자 (공장·절곡업체 등) | 주문 접수, 출하 등록(품목·길이·중량·수량), 상차 사진, 납품서 발행 |
| 현장 (구매자) | 현장 정보 등록, 도착 알림, 인수 확인(사진·서명), 수량 부족·하자 신고 |
| 화물기사 (별도) | 배차 수락, 상차→출발→도착→하차 단계 보고, GPS 위치 전송, 내 차량 등록 |
| 공유 링크 | **앱 설치 없이 HTML 링크로** 지도·현재 위치·도착 예정·단계를 조회 |
| 이음비 운영자 | 구독 요금제·수수료 설정, 차량 규격 표 관리, 정산 내역 |

## 2. 사용자가 정한 것 (2026-11-13)
1. 앱 이름: **운송비**
2. 화물기사는 **별도 주체** (생산자 직접 배송이 아님)
3. 차량 종류 선택 필요 + **차량별 적재함 크기 안내**
   - 기본 차량: 1톤 / 2.5톤 / 3.5톤 / 5톤 / 11톤 / 25톤 × 카고·윙바디·카고크레인
   - 차량 종류는 **나중에 추가 가능**하게 (운영자가 추가, 기사는 내 차량 실제 치수로 수정)
4. 운임 부담: **발주자·생산자·현장 모두 가능** → 주문마다 결제 주체 선택
5. 현장 정보 등록: 반입 가능 시간, 하차 장비(지게차·타워크레인 등), 현장 담당자 연락처, 출입 경로·주의사항
6. **GPS로 현재 운반 상황 표시** → 발주자·생산자·현장 모두 확인, **앱을 깔지 않아도 링크로 조회**
7. **구독 + 수수료 체계** 도입
8. 차량마다 **3D 적재함을 치수선과 함께** 표시
9. **구독료·수수료 금액은 이음비(본체)에서 수정**할 수 있게 함 — 다른 비(공간비·절곡비·노무비)도 같은 방식으로 이미 설정되어 있음

## 3. 이음비 본체에 반영할 사항 (이음비 세션에 전달)
- 이음비 요금 관리 화면에 **운송비** 항목 추가
  - 구독 요금제(역할별·기간별), 건당 수수료(정액 또는 운임의 %), 결제 주체별 적용
  - 다른 비와 같은 설정 구조·테이블을 그대로 사용 (새 구조 만들지 말 것)
- 운송비 앱은 금액을 코드에 고정하지 않고 **이음비 설정값을 읽어서** 사용
- 금액·요율은 미정 → 시제품에서는 "가정값"으로 표시

## 4. 기술 처리 방침
### GPS
- 시제품: 가상 이동 경로로 위치 이동 시연
- 실제 운영: 휴대폰 웹페이지는 백그라운드로 가면 위치 전송이 멈추는 경우가 많음
  → **기사용은 앱(또는 화면 켜 둔 상태 유지)**, 조회하는 사람(발주자·생산자·현장)은 **공유 링크**로 보는 구조 권장
- 위치 저장: Supabase (Realtime 구독으로 지도 갱신 예상) — 서버 단계에서 확정
- 지도: 카카오맵 또는 네이버 지도 API (키 발급 필요, 선택은 서버 단계에서)
- 공유 링크: 운송 건마다 추측하기 어려운 토큰 URL, 운송 완료 후 만료 시간 설정

### 3D 적재함
- Three.js 사용, 차량 선택 시 적재함 상자 + 길이·너비·높이 치수선(mm)
- 자재 크기(길이×폭×높이, 수량)를 넣으면 **적재 가능 여부 표시** (길이 초과·높이 초과·중량 초과)
- 중량 초과 판단은 차량 최대적재량 기준, 법정 기준은 별도 확인 후 반영

## 5. 운송 단계 (상태값)
`requested(요청)` → `accepted(배차)` → `loading(상차)` → `departed(출발)` → `arrived(도착)` → `unloaded(하차·인수)` → `settled(정산)` / 예외: `cancelled`, `issue(수량부족·하자)`

## 6. 데이터 모델 (서버 테이블 초안)
| 테이블 | 주요 항목 |
|---|---|
| orders | 발주자, 생산자, 현장, 품목 목록, 희망 반입일시, 운임 결제 주체, 상태 |
| order_items | 품명, 재질, 길이·폭·높이, 수량, 단위중량, 총중량 |
| sites | 현장명, 주소·좌표, 반입 가능 시간, 하차 장비, 담당자·연락처, 출입 경로, 주의사항 |
| vehicle_types | 톤수, 차종(카고·윙바디·카고크레인 등), 적재함 장·폭·고, 최대적재량, 출처, 확인 여부 — **운영자가 추가** |
| drivers / driver_vehicles | 기사 정보, 차량번호, 차종, **실제 적재함 치수** |
| shipments | 주문, 기사, 차량, 상태, 단계별 시각, 상차·인수 사진, 서명, 운임 |
| locations | shipment_id, 위도, 경도, 속도, 시각 |
| share_links | shipment_id, 토큰, 만료 시각 |
| billing | 이음비 공통 요금 설정 참조(구독·수수료), 결제 내역 |

권한(RLS): 기사는 배차된 건만, 생산자·현장·발주자는 자기 주문만, 공유 링크는 토큰으로 해당 운송 건 조회만 가능.

## 6-1. 대화 기능 (2026-11-13 추가)
- 운송 건마다 `messages[]` 배열 — 4자(발주자·생산자·현장·화물기사) + 공유 링크 방문자가 대화
- 각 역할의 **진행 현황** 탭과 **공유 링크** 화면에 대화 칸 표시
- 메시지 구조: `{role, name, text, time}`
- 공유 링크: 이름 입력 칸(로그인 없음, sessionStorage에 기억) + 메시지
- 서버 버전: Supabase Realtime으로 실시간 대화, messages 테이블(shipment_id FK, RLS = 해당 운송 건 관계자 + 공유 토큰)

1. 이음비 저장소에서 운송비 색상·공통 디자인 확인 (노무비 v2 틀 참고)

   - 주문→출하→배차→운송(가상 GPS)→인수 흐름
   - 3D 적재함 + 치수선 + 적재 가능 여부
